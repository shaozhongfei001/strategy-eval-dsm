# ORCH-06 S1-T01 首轮取证判为 L0 未通过，扩大取证范围与方式

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-23 |
| 阶段 / 任务 | S1 / S1-T01 |
| 裁决人 | Orchestrator（主控） |
| 类型 | 流程裁决（L0 门禁适用） |

## 事实

R1 首轮按 ORCH §5.2 给定的四个行区间取证后，如实标注 6 类下游验收项落在授权区间外，
并**拒绝自行补口径**：ScoringContext、Frame/PoolStats 字段、Ratio/MoneyMinor 注解类型、
recommended_action 与 decided_action 分列、TODO|TBD|XXX 拦截串、attainment_floor 单调性、P-11。

## 裁决

1. 首轮 S1-T01 判为 **L0 未通过**。依据 ORCH §7.2：L0 的通过判据是
   「digest 覆盖该任务全部验收项所需原文」，覆盖不全即不合格，与产物质量无关。
2. 授权扩大取证范围，取证**方式**限定为：`grep -n` 按词定位行号 + `sed -n 'A,Bp'` 取定位到的区间。
   `grep -n` 只回匹配行，不构成 ORCH §1.2-1 / §11-1 所禁止的「全文重读」，符合其省 token 的立法意图。
3. 已落盘的 digest 不得改写，只能追加新文件（§1.2-4）。

## 依据

ORCH §7.2 L0 判据；§1.2-1/§1.2-3/§1.2-4；§11-1；§10.2-4。

## 影响

S1-T01 增加两轮往返（定位 → 摘录）。换来的是 S1-T02~T07 六个任务无需再碰原文，
按 §11-2 的 token 纪律，净收益为正。
