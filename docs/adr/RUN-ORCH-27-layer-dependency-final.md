## 二、裁决

**驳回 E5 的合法性判定，维持 ORCH-26 的「数据注入」修复方向。**

1. **L276 + L286 是 L0a 的定义性约束**：「不依赖任何内部层」「无内部依赖（独立命令行工具）」。L278 的「**消费** L0a 与熵权快照」只能读作消费 L0a 的**产物快照（数据）**，不能读作 import L0a 的**模块**——否则 L278 与 L286 直接冲突，而「数据注入」读法可让两行**同时成立**。按 R-12（不编造）与「不得弱化守护」的原则，采唯一不产生矛盾且不放宽任何一条的读法。
2. **L282 印证同一读法**：拆 L0a/L0b 的动机是「L0b 需要跑 Step 1–7 流水线，故依赖 L1–L4」，即**跨层依赖只允许指向 L1 及以下业务层**，从未授权 L0 层内部互相 import；且明写「拆分后依赖仍**严格单向**」。
3. **`ALLOWED['L0b']` 不得放宽**：L294 逐字为「L0b → L1-L5（单向调用；反向禁止）」，`L0a` 与 `L6` 均不在其中。E5 建议的放宽属弱化守护，**驳回**。
4. **L0a → L1 的例外予以维持**（ORCH-03 先例）：SDD §2.4.2 L537 要求熵权六步「两个计算者共用同一实现」，两个计算者是 `weights_combine`（L0a）与 `diagnostics`（L5）；若 L0a 连 L1 都不得 import，则该要求与 L286 不可同时满足。故 L286 的「无内部依赖」读作**「无 L0 / L2+ 依赖」**，L1（`numeric` 唯一数值口径、`entropy` 唯一熵权实现、`reason_codes` 唯一注册表）作为全系统共用原语层为例外。**此例外必须写入 P3a 披露。**
5. **`test_t05_m03` 不做 triage**：其判据「任何 dsm 模块不得 import L0 模块」在上述读法下与原文一致（L0a 不得 import L0a；L0b 只可 import L1-L5），修掉生产侧 import 边即自然转绿。**禁止改该断言。**
6. **E5 的 `ALLOWED['L0a']` 需收紧**为 `('L1',)`（去掉 `'L0a'`）。收紧断言属允许动作（弱化才禁止），由 E5b 执行。
