# ORCH-09 L6 落库（R5）由 Orchestrator 直接执行的职责裁定

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-23 |
| 阶段 / 任务 | 全阶段（S1~S9） |
| 裁决人 | Orchestrator（主控） |
| 类型 | 流程裁决（职责边界澄清） |

## 冲突

ORCH §4 把 R5 Integrator 列为子智能体角色（rsync + normalize + 全量回归 + 编码校验 +
commit/push + 写状态文件，默认 flash）；而 §0 把「⑤ 维护状态文件与阶段对账单」
明确划为**主控只做五件事**之一，且 §4 并发规则要求「由 R5 **串行**落库」。
二者对状态文件的归属存在重叠。

## 裁决

L6 落库由 Orchestrator 直接执行，不再派 R5 子智能体。**理由**：

1. §0-⑤ 已把状态文件维护划归主控，主控对状态文件的内容负最终责任，不可外包其判断；
2. §4 要求落库**串行**，而串行点天然只有一个，就是主控；再派一个 agent 只会增加一次交接与一份 token 开销；
3. R5 的其余动作（rsync / normalize / 全量回归 / 编码校验 / commit / push）全部是**机械且有客观判据**的动作，
   主控执行时同样要逐项核对实测输出才能裁决通过，派给子 agent 不增加任何独立性；
4. **§4 的职责分离骨架未被破坏**：其立法目的是「实现者与复核者必须是不同 agent 实例，
   且复核者不读实现者的推理」。本裁决下 R3（测试先行）、R2（实现）、R4（独立复核）
   仍全部是互相独立的子智能体实例，R4 仍只拿 digest + pytest 输出 + git diff。

## 保留的强制项（不得因本裁决而省略）

- 每次落库前：`git status --porcelain` 确认改动只在当前任务写集内（§10.1-3）
- 每次落库前：`tools/normalize.py --check` 必须报 0（H-3）
- 每次落库前：全量 `pytest` 必须 0 failed / 0 error / 无新增 skip（§7.3 收敛判据）
- push 前：`git ls-remote origin` 探活（H-12）；禁止 `--force`、禁止改历史
- 落库后：立刻更新 `ops/dag-state.json`（§8）

## 依据

ORCH §0、§4（角色表 + 并发规则）、§7.2 L6、§7.3、§8、§2 H-3/H-12、§10.1-3。

## 影响

减少每任务一次子智能体往返；状态文件与对账单的一致性由单一责任人保证。
