# ORCH-05 digest 单文件 120 行上限下的拆分处置

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-23 |
| 阶段 / 任务 | S1 / S1-T01 |
| 裁决人 | Orchestrator（主控） |
| 类型 | 流程裁决（不改任何设计口径） |

## 冲突

ORCH §1.2-2 规定每个 digest 文件 ≤ 120 行；而 §5.2 给 S1-T01 的授权区间
（§3.3.3 L860-873、§3.11.1-3.11.4 L1093-1245、§5.8.1 L1886-1904、§3.12 L1246-1261）
原文合计 202 行，且 S1-T02~T07 六个任务**只读 digest 不读原文**（§1.2-3），
压缩进单文件 120 行会丢失下游开工所需的契约细节。

## 裁决

按主题拆分为多个 digest 文件，每个仍严格 ≤ 120 行，全部登记进 `docs/digest/INDEX.md`：
`S1-T01.md`(models) / `S1-T01b.md`(config) / `S1-T01c.md`(config 补全) /
`S1-T01d.md`(中间与输出模型) / `S1-T01e.md`(验收判据与 K 清单)。

## 依据

- ORCH §1.2-2（≤120 行是**每文件**上限，未限制文件个数）
- ORCH §1.2-4（digest 一旦落盘即复用，后续任务**只能追加**）——追加的自然单位就是新文件
- ORCH §7.2 L0 通过判据（digest 必须覆盖该任务全部验收项所需原文）优先级高于单文件行数偏好

## 影响

不改任何模块职责与设计口径；仅取证产物的物理组织方式。
